# gcalsorter

A Chrome extension that lets you **drag to reorder the member columns** in Google Calendar's day view.

Google orders those columns for you, and gives you no way to change it. This puts a small grip on each
column header so you can drag the people you actually care about next to each other, and remembers the
order you chose.

## What it does

- Reorders the day view's member columns by dragging the grip at the top-left of a column header.
- Your own column stays pinned leftmost. The date label lives inside it, so moving it would drag the
  date away from the left edge.
- Remembers one global order and applies it to every day.
- People you hide by unchecking their calendar keep their place in the saved order, so re-enabling
  them puts them back where they were rather than at the end.
- People not in the saved order yet are appended, keeping Google's relative order among themselves.
- Only ever touches the day view. Week, month and every other view are left completely alone.

## Install

```sh
npm install
npm run build
```

Then load `dist/` through `chrome://extensions` → Developer mode → **Load unpacked**.

## Popup

The toolbar popup shows the saved order, lets you turn reordering off without uninstalling, and resets
the order. It also reports why nothing is being applied, if that happens.

## How it stays alive

Google Calendar's class names are generated by its build and change without notice, and the day view
rebuilds its columns constantly. A few notes on what that forces, all of it measured against the live
app rather than guessed — see [docs/SPEC.md](docs/SPEC.md) for the measurements:

- **The view is read from the DOM, not the URL.** Chrome's "install as app" window opens
  `calendar.google.com/calendar/r` and renders the day view without putting `day` in the path, so the
  day view is recognised by the page carrying exactly one distinct `data-datekey` instead.
- **No class names, no fixed sizes.** Columns are found by measuring the `[role="columnheader"]`
  rectangles at runtime and matching other rows against them geometrically. Column width varies with
  window size and member count, so nothing is hardcoded.
- **Five containers, not one.** The columns of a single day view are spread across five separate flex
  containers. Missing one leaves that layer unsorted, silently.
- **It checks its own work.** After setting the CSS `order`, it measures the columns again. If anything
  did not land where intended, it rolls the whole thing back and leaves you with a plain, working
  calendar.
- **Nothing moves in the DOM.** Only inline `order` — plus, on the two columns that need it, the
  `border-right` that Google attaches to whichever column is last in DOM order — is set on Google's
  elements. Grips, the drag ghost and the insertion line are drawn in the extension's own overlay.

## Development

```sh
npm run watch      # rebuild on change
npm test           # unit tests for the order-resolution logic
npm run typecheck
npm run lint
```

The order-resolution logic is pure and covered by tests. Column detection and applying the order depend
on real layout — `jsdom` reports every rectangle as zero — so those are verified by hand against the
live calendar.
